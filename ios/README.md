# Bible Lantern for iOS

A SwiftUI shell around the live site (`https://www.biblelantern.com`) in Apple's Liquid Glass chrome: the system's
floating glass tab bar (Home · Read · Study · Library · Profile), a glass Read toolbar (book and chapter picker,
translation, search, Explore, share) with a chapter stepper floating above the tab bar, universal links, a sign-in
that sticks. The page runs edge to edge beneath the bars and does the reading; every fix to the site reaches the app
at once. iOS 26 and later (the glass APIs). The plan is `.design/ios-brief.md` (§6 for the glass).

## What is here

- `BibleLantern.xcodeproj` — generated by `gen_project.py` (Xcode 16 format, a synchronised folder: every file under
  `BibleLantern/` is in the app target, so new files need no project edit; a shared scheme). Bundle id
  `com.biblelantern.app`, iOS 26+, iPhone and iPad.
- `BibleLantern/Shell/` — `WebController` (the one web view, the `bl` message handler, the `BL.*` calls, navigation
  policy: the site stays in the app, other sites open in Safari), `AppModel` (the tab, the sheets, how the page's
  state moves the tab, universal links, share, Dynamic Type), `Bridge` (the message types), `Site` (URLs, user agent).
- `BibleLantern/UI/` — `RootView` (the `TabView`, the sheets, the loading view), `ReadToolbar` (`ReadChrome`, the
  Read tab's toolbar; `ChapterStepper`, the bottom accessory; `TranslationMenu`), `ExploreSheet`, `BookPicker`,
  `SearchSheet`, `ProfileView`, `ShareSheet`. `Shell/WebView.swift` holds `WebPane`, the container that adopts the
  one web view in whichever content tab is selected.
- `BibleLantern/Assets.xcassets` — the app icon (the engraved lantern mark, 1024px), the accent colour (the site's
  link blue, light and dark), the launch background (the site's page colours).
- `Config/` — `Info.plist` (the `biblelantern://` scheme, the launch screen colour, no non-exempt encryption; merged
  with the generated Info.plist), the entitlements (associated domains for universal links), and the
  `apple-app-site-association.json` template for stage 4.

## The bridge (web side, in the main repo)

Inside the app the page runs in **app-shell mode**: `index.html` adds `html.app-shell` before the first paint when the
user agent contains `BibleLantern/iOS` (or the URL has `?app=ios`, for a desktop check); `styles.css` then hides the
top bar, takes `--bar-h` from `env(safe-area-inset-top)` (the glass toolbar's height, so the chapter hero and the
scroll padding sit below it), pads the bottom for the tab bar, runs Home's cover under the status bar and keeps form
fields at 16px (no focus zoom); `main.js` loads `app/js/shell.js` at the end of boot, which:

- exposes `window.BL`: `open('home'|'read'|'study'|'library'|'profile'|'settings'|'picker'|'43/3/16'|'John 3:16')`,
  `panel('arcs'|'graph'|'map'|'art'|'')`, `search(q)`, `step(±1)`, `stepVerse(±1)`, `setTranslation(id, 'tr'|'tr2')`,
  `setFontSize(px)`, `setTheme('auto'|'light'|'dark')`, `setOrig(bool)`, `closeOverlays()`, `signOut()`, `share()`,
  `state()`, `books()`, `translations()`;
- posts `ready` once and `state` on every change (hash, verse, dialog, Home, theme, sign-in) to
  `window.webkit.messageHandlers.bl` — in a desktop browser the messages wait in `BL.outbox` instead.

On the open web nothing changes: without the user agent or the flag the module never loads.

## Building and running

1. Xcode from the Mac App Store (the command-line tools alone cannot build for iOS), then
   `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` and, for a simulator, the iOS platform:
   `xcodebuild -downloadPlatform iOS` (several GB; let it finish).
2. Open `ios/BibleLantern.xcodeproj`. In the target's Signing & Capabilities pane choose your team (automatic
   signing); Xcode writes the team id into the project. Or from a terminal:
   `xcodebuild -project ios/BibleLantern.xcodeproj -scheme BibleLantern -destination 'generic/platform=iOS Simulator' build`.
3. Run on an iPhone simulator (⌘R). The app loads the live site; sign in with your own profile.

**Until the bridge is deployed** (PR #6), the live site has no app-shell mode, so the app shows the page as it is
after a few seconds (its own top bar, no tab following). To test the real thing, serve this branch locally
(`python3 serve.py --port 8861 --data-dir .design/linkstest/ios-shell`) and point a Debug build at it:

```bash
xcrun simctl spawn booted defaults write com.biblelantern.app bl.site http://localhost:8861
```

Delete the key (`defaults delete com.biblelantern.app bl.site`) to go back to the live site. Release builds ignore it.

Universal links (stage 4) need the team id in `Config/apple-app-site-association.json`, served from the site at
`/.well-known/apple-app-site-association` as `application/json` (a `vercel.json` header rule).
