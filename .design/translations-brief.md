# NIV, NKJV and NASB in the reader, through API.Bible (build brief, stage TR1)

Ji (2026-10-22) asked for NASB, NKJV, NIV and ESV. ESV stays as it is for now (Crossway's own API, owner-only until Ji registers the site with Crossway). This stage adds **NIV, NKJV and NASB** through **API.Bible** (`https://rest.api.bible/v1`, Starter plan: free, non-commercial, three licensed Bibles, 5,000 calls a month). Ji puts the key in Railway as **`BS_APIBIBLE_KEY`**; nobody else handles it, and it must never reach a browser, a log line or a response.

API facts (docs.api.bible; build to these, and make the parser tolerant):
- Auth header `api-key: <key>`. `GET /v1/bibles` lists the Bibles the key may use (`data[]` with `id`, `abbreviation`, `abbreviationLocal`, `name`, `language`…). `GET /v1/bibles/{bibleId}/chapters/{BOOK}.{n}` (book ids `GEN`…`REV`, USFM: `JHN.3`, `PSA.23`, `1JN.4`, `SNG.2`, `EZK.37`, `JOL.2`, `NAM.1`, `JAS.1`, `PHP.4`…) with `content-type=json&include-notes=false&include-titles=false&include-chapter-numbers=false&include-verse-numbers=true&include-verse-spans=false&fums-version=3`.
- Response `{data: {id, bibleId, number, bookId, content, reference, verseCount, copyright, next, previous}, meta: {fumsToken, …}}`. JSON `content` is a tree of `{name, type: 'tag'|'text', attrs, items}`: verse markers `{name: 'verse', attrs: {number, sid}}`, text nodes `{type: 'text', text, attrs: {verseId: 'JHN.3.16'}}`. Attribute each text node to its `verseId`'s verse number; a psalm's title (USX style `d`, text without a `verseId` before verse 1) goes to `title`, as the ESV/NLT fetchers do; footnotes and headings never into verse text.
- Caching is allowed and encouraged but must be refreshed within 30 days (API.Bible terms); refresh after **14 days**. Text must stay unaltered; the publisher's `copyright` must be shown with every display. **FUMS v3** is required on the web (and in the iOS app's web view): load `https://pkg.api.bible/fumsV3.min.js` (with the queueing stub that defines `window.fums` first), and call `fums('trackView', fumsToken)` each time a chapter of a licensed text is shown (a parallel column counts). FUMS sends no personal information; its script makes its own device and session ids.

## 1. Server (serve.py, tests/test_server.py) — stage 1

- `BS_APIBIBLE_KEY` from the environment (hosted on Railway; locally too, for Ji's own copy), optional `BS_APIBIBLE_URL` (default `https://rest.api.bible/v1`, so tests can point at a local fake) and optional `BS_APIBIBLE_BIBLES` (`niv=<id>,nkjv=<id>,nasb=<id>`) to pin ids. Without pinned ids, discover them once from `/v1/bibles` by abbreviation (NIV; NKJV; NASB, then NASB2020, then NASB1995 / NASB95), keep the map in memory and on disk under `DATA/cache/apibible/bibles.json` (re-discover after 14 days or when a chapter call says the id is unknown).
- Translations `niv`, `nkjv`, `nasb` join the passage proxy: `GET /api/passage?tr=niv&book=43&chapter=3` → `{verses: [...], title?, copyright, fumsToken, fetched, v}` in the same shape ESV/NLT return, cached under `DATA/cache/<tr>/BB-C.json`, refetched when older than 14 days. Same same-origin check, the existing `UPSTREAM_WINDOW` limiter, and a refused chapter that does not exist, as today.
- **Open to everyone**, hosted guests included (unlike ESV/NLT, which stay owner-only): this licence is for the public site.
- **Monthly budget:** count upstream calls per calendar month (on disk with the cache, survives restarts); past `BS_APIBIBLE_MONTHLY` (default 4,800) refuse new upstream calls with `429` and a plain message (cached chapters keep being served). Add the month's count to the owners' Site activity report (`/api/admin/traffic`: `apibible: {calls, limit}`) and an `[alert]` log line once when 80% is reached.
- `GET /api/config` gains `licensed: ['niv', 'nkjv', 'nasb']` (the ones the key can serve; empty without a key or when discovery found none) for every session.
- Errors: a 401/403 from API.Bible, a timeout, an empty chapter: `502` with a plain message, never cached, never including the key. Never log the key or the full upstream URL with it.
- Tests (with a local fake API server): discovery and pinning, the JSON content parser (verse attribution across paragraphs and `wj` spans, a psalm title, a verse with no text, footnotes excluded), the cache and its 14-day refresh, the monthly budget, hosted guest allowed for `niv` but still refused for `esv`, `config.licensed`, the key absent from every response and log line. All existing tests keep passing.

## 2. Client — stage 2 (app/data/meta.json or store.js, main.js, reader.js, app/privacy.html, app/js/shell.js, ios/BibleLantern/UI/ReadToolbar.swift)

- Translations NIV, NKJV and NASB: when `config.licensed` includes one, it is a normal in-app text (primary and parallel, in the translation menus, for everyone), labelled by abbreviation; when it does not, NIV and NKJV keep today's "Opens a website" (Bible Gateway) and NASB joins them as a Bible Gateway link (`version=NASB`). A guest on the hosted site can choose them (they are not owner-only).
- Below a chapter of a licensed text (and below each parallel column's text, if they differ), the publisher's `copyright` line, small and quiet, in the reader's footer area (never in the chapter hero, which must stay byte-identical: hero check).
- FUMS: the script loads lazily the first time a licensed chapter is shown; `fums('trackView', token)` on each display (primary and parallel), not on re-renders of the same chapter without a new display (a scroll, a selection). Not in `?dry`.
- Search, cross-reference previews and other places that show verse text in the current translation: use the licensed text where the code already uses ESV/NLT passages, and fall back to KJV where it already does for ESV/NLT; never hit API.Bible in a loop (previews of 50 other chapters must not cost 50 calls: use the existing preview fallback rules).
- Privacy page (`app/privacy.html`): one sentence under "Services we rely on" for API.Bible's fair-use count (which licensed chapters are shown, no personal information, its own device and session ids), and adjust the app line so it stays true ("no analytics or third-party tracking code, apart from the publishers' fair-use count when you read NIV, NKJV or NASB"). Keep the page's tone.
- iOS shell: `BL.translations()` reports these with a kind the native menu shows (update `TranslationMenu`'s filter in ReadToolbar.swift to include the new kind; `swiftc -parse` it).
- Copy rules: sentence case, curly quotes, British spelling, no exclamation marks.
