# Bible Lantern for iOS: build brief

Ji asked (2026-10-19): after the Study feature ships, "get started on making an iOS mobile app version of this, optimising for mobile app interface and ease of use, consolidating the menu etc, for the iOS App Store."

## 0. Approach: a native shell around the live site

A SwiftUI app whose content is the live app at `https://www.biblelantern.com` in a `WKWebView`, with native chrome and native features around it. Every fix to the site reaches the app at once; the native layer gives Apple the "minimum functionality" it requires (App Review guideline 4.2) and gives readers what a phone app should have. A full native rewrite is not planned; native screens can replace web ones later where they earn it.

Constraints: Xcode must be installed on this Mac (today only the command-line tools are present); an Apple Developer account in Ji's name is needed to submit (Ji signs up; nothing here needs it until then). Bundle id `com.biblelantern.app`, display name **Bible Lantern**, iOS 17+, iPhone first with iPad adapting.

## 1. The native layer

- **Bottom tab bar** (replaces the phone's two-row top bar): **Home · Read · Study · Library · Profile**. Each tab is the web app at a route; the web app hides its own top bar when it runs inside the shell (a `?app=ios` flag or a `BibleLantern/iOS` user agent that `main.js` reads to apply an `app-shell` class). Selecting a verse, the study sheet, search, the visualisations and the Doré viewer stay as they are inside Read.
- **Read toolbar**, native, one row: current reference (opens the native book/chapter picker), translation, search. The visualisations move into one native **Explore** sheet (Arcs · Graph · Map · Art) that asks the web app to open the panel. Original (interlinear), theme and settings move to **Profile**.
- **Sign-in that sticks**: the site's session cookie persists in the web view's data store; Profile shows the signed-in state natively and offers Sign out.
- **Offline reading**: the app pre-caches `meta.json`, the KJV and BSB chapter files, and the chapters the reader has opened, via a `WKURLSchemeHandler` or a service-worker-style cache in the web app; a chapter opens without a network, and writes queue until it returns (the web app's data layer already tolerates offline).
- **Verse of the day widget** (small and medium) from the same curated list Home uses, with a deep link into the verse; an optional **daily notification** at a chosen time.
- **Share sheet** for a verse or a highlight ("John 3:16 — … biblelantern.com/#43/3/16"), and **universal links** so `biblelantern.com/#book/chapter` opens in the app.
- **Native pickers** for book and chapter (a wheel or a grid), haptics on selection, Dynamic Type passed to the web app's font-size setting, Reduce Motion honoured.
- **App icon** from the engraved lantern mark (`.design/logo/out/mark-dark.svg`), launch screen in the app's dark palette.

## 2. Web app changes (small, in the main repo)

- `app-shell` mode: hide the top bar and the Home top bar, expose a small `window.BL` bridge (`open(route)`, `panel(name)`, `search(q)`, `setFontSize(n)`, `onAuthChange`, `onRouteChange`) using `WKScriptMessageHandler`, and report the current route and auth state to the shell.
- Keep everything working on the open web exactly as today.

## 3. App Store

- Privacy: no tracking; the profile data stays on the reader's server account; a privacy policy page on the site (`/privacy`) is needed, plus Sign in with Apple is **not** required because the app has no third-party sign-in (only its own email + password).
- Screenshots from the simulator at 6.7" and 6.1"; the description from the site's own copy; category Reference or Books; age rating 4+.
- Review notes: a test account on the site for the reviewer (created by Ji, not by me).

## 4. Stages

1. Xcode project scaffold, tab bar, web view with the shell bridge, sign-in persistence, universal links; the web app's `app-shell` mode.
2. Native Read toolbar, Explore sheet, book/chapter picker, share sheet, Dynamic Type.
3. Offline cache, widget, notification.
4. Icon, launch screen, privacy page, screenshots, TestFlight build, App Store listing.

## 5. Stage 1 as built (2026-10-19, branch `ios`, `ios/README.md`)

Built without Xcode (only the command-line tools are installed): the Xcode 16 project is generated by
`ios/gen_project.py`, every Swift file passes `swiftc -parse`, the web side is tested in a browser with `?app=ios`.
Deviations from §1: the Original (interlinear) toggle sits in the Explore sheet as well as in Profile, because it is a
reading tool; the Read toolbar carries Share; the parallel translation is in the translation menu. Stage 2 starts
when Xcode is installed and the app runs on a simulator.

## 6. Liquid Glass (Ji, 2026-10-19: “modernize the look of the app with the latest apple frosted glass look”)

The shell adopts Apple's current design language rather than drawing its own bars:
- **Tab bar**: SwiftUI `TabView` with `Tab` values (Home · Read · Study · Library · Profile), so the system draws the
  floating glass tab bar, its selection animation, VoiceOver and the iPad form. The one web view moves between the
  content tabs (a container per tab adopts it when that tab is selected); Profile stays native.
- **Read chrome**: a `NavigationStack` toolbar on the Read tab (glass, automatically): the reference button leading,
  translation · search · Explore · share trailing with a `ToolbarSpacer`; the chapter stepper lives in a
  `tabViewBottomAccessory` above the tab bar, close to the thumb (‹ John 3 ›), only on Read.
- **Edge to edge**: the page extends under the bars (`ignoresSafeArea`); WebKit insets the scrolling and exposes the
  insets as `env(safe-area-inset-*)`, and app-shell mode sets `--bar-h: env(safe-area-inset-top)` so the chapter hero,
  the scroll padding and the study sheet sit below the glass as they sat below the old bar.
- **Sheets** (Explore, picker, search) and Profile's list are standard, so they are glass already; buttons that float
  use `.buttonStyle(.glass)`.
- **Deployment target iOS 26** (from 17): the glass APIs exist only there; the website serves everyone else. The
  bottom accessory needs 26.1 and is gated.
- **No giving inside the app** (App Review 3.1.1): Profile has no Support row and app-shell mode hides the page's
  donate links (the sign-up pause keeps its words); the open web is unchanged. Pending Ji's call.
